一、实施总纲

本文是《油气储运NF痛点与解决方案汇总》（需求基线）的行动篇：基线文档定义了 NF「做什么、必须满足什么」，本文回答「怎么一步步做出来」。NF 的全部机制都可以在 TeleAgent Desktop 上用三块现成能力搭建——Skill 系统（角色路由与工作流）、MCP 本地服务（确定性计算引擎）、定时任务（每日自检与报告），不需要另行开发桌面软件。

三条落地原则（贯穿全程）：

  • 先机制后内容——先把骨架搭好、规则立住，再灌入内容；机制不牢，内容越多越乱；
  • 先窄后宽——一期只做一个切入场景，跑通验证后再扩展角色，贪多必散；
  • 先跑通再扩展——每个阶段都有明确验收标准，未通过不进入下一阶段。

二、阶段 0 · 准备：原料与两个决定

NF 的一切建立在真实文件之上（反幻觉防线一：白盒启动），所以第一步不是搭系统，而是盘点你手头的「原料」。原料的完备程度直接决定一期效果。

表 2 阶段 0 原料清单
材料类别 具体内容 一期建议量 用途
正版规范电子版 GB/T 9711、GB 50251、GB 50369 及常用 SY/T 系列（官方渠道获取） 10–15 本 规范卡片来源；版本状态联网核实的对象
教材与讲义 水力学、传热、油气集输、腐蚀与防护等核心教材 3–5 本 公式卡片与参数物理意义解释的来源

实验指导书 流阻测定、物性检测、腐蚀测试、流量计标定等 按需 实验卡来源（一期可选，二期主线）

同时做两个决定：

  • 决定一 · 首个切入场景：建议选择「学生日常学习」——规范查询 + 公式计算，使用频率最高、验证反馈最快，且是后续所有场景的地基。若你更倾向课程设计引导或教师资源建设，在阶段 1 开始前告知即可，机制框架不受影响；
  • 决定二 · 校核人：你自己或 1–2 位专业教师，负责阶段 2 的卡片校核转正与阶段 3 的回归结果复核。这是不可省略的角色——反幻觉与计算可靠性承诺的兑现，最终都落在人工校核这一环。

原料红线：规范电子版必须来自官方正版渠道——非官方渠道流传的「电子版」可能被篡改、缺页、混入旧版内容，是数据污染源（需求基线 8.1 收录红线）；同时全部文件在本地解析、不上传不出电脑（数据边界）。

三、阶段 1 · 机制框架：搭起可运行的空骨架

用平台现成工具搭三件套。此阶段产出的是一个「空但能跑」的系统——知识库里一张卡片都没有（刻意的白盒启动），但全部规则已经立住。

① 主 Skill

用 skill-creator 搭建。SKILL.md 只写身份先行路由与工作流（首次使用询问身份→主推/次推分流→身份可切换），知识全部外置 references/ 目录：规范卡、公式卡、介质卡、决策树、清单模板各占子目录——SKILL.md 保持精简，不稀释注意力。

② 计算引擎 MCP

用 mcp-builder 搭建本地 stdio 服务。一期四模块：单位换算与量纲校验、水力计算（雷诺数→流态判别→沿程阻力→压降）、温降计算、壁厚计算；每个接口固定输出计算书（输入、公式版本、中间量、判据对照）。

③ 白盒知识库

知识库目录空库初始化——此时库里一张卡都没有，这是反幻觉防线一的落实。空库状态下提问会得到「未收录，建议补充文件」，这个「诚实的不知道」正是防线三在工作。

阶段 1 验收要点：骨架可运行、规则可见效——空库可正确回答「未收录」而非编造；MCP 四模块可被调用并返回带计算书的结果（数值正确性留待阶段 3 验证）；身份先行路由正确——首次使用主动询问身份，选定后相关入口置顶、其余降级可及，一句话切换后主推内容立即重排。

四、阶段 2 · 内容灌入：真实文件变成转正卡片

本阶段开始把阶段 0 的原料转化为知识库内容，节奏是「解析一批、校核一批、转正一批」，全部执行需求基线 6.1 的五步流程：

  1. ① 文件投喂

    用户把规范、教材、例题文件放入指定目录，全程本地解析，不出电脑。

  2. ② 本地解析

    PDF 与 OCR 解析保留条文号、页码与表格结构，形成带精确定位信息的原文片段。

  3. ③ 卡片草稿

    助手由解析片段生成卡片草稿，自动携带溯源（文件名、页码、条文号、提取时间），统一标注「待校核」。

  4. ④ 人工校核

    校核人对照原文逐条核对草稿，修正错漏后转正——这步由你或专业教师执行，不可省略。

  5. ⑤ 入库生效

    只有转正卡片参与回答与计算；「未转正不参与回答」作为规则写入 Skill 强制执行。

五、阶段 3 · 引擎验证：证明「不乱给结果」

阶段 1 搭好的计算引擎此时接受检验——用阶段 0 收集的手算例题做基准回归：每道题的教材手算答案与引擎输出逐单元比对（雷诺数、流态、沿程阻力、压降逐项核对，不是只对最终数）。

  • 回归对象：20–30 道手算例题（教材例题 + 课程设计真题），覆盖一期四模块全部公式；
  • 通过标准：全部基准题通过，偏差在有效位数内一致；
  • 阻断机制：任何公式偏差超过阈值（如 0.1%）即冻结该公式对外输出，修复并重新通过回归后才恢复——未通过回归的公式，NF 就是拒算，这是「不乱给结果」承诺的实际兑现；
  • 计算书核验：抽取若干结果，由校核人按计算书逐项手工复算，确认七项内容（输入、公式版本、常数来源、中间量、结果、判据对照、告警）完整可核。

为什么必须人工复核：基准题答案本身也可能有印刷错误或版本差异——回归发现引擎与教材不一致时，先核对教材原文再判定是谁错了。这类「冲突排查」记录本身也是宝贵的知识库内容（易错点卡片素材）。

六、阶段 4 · 定时任务：让数据库活起来

用平台 scheduler 建立每日定时任务，按需求基线 8.3 编排五件事，并落实 8.4 的每日报告机制：

  1. ① 数据库健康自检

    卡片元数据完整性、引用死链、重复与孤儿卡片、逾期复查标记。

  2. ② 计算引擎回归

    基准题集每日全量回归（联动闸门二），偏差超阈即冻结告警。

  3. ③ 官方渠道扫描

    标准发布、实施、替代、废止动态检测，触发核实流程与生效日切换。

  4. ④ 事件库分级收录

    事故通报、政策、辟谣、撤稿按五级可信度收录入独立事件库。

  5. ⑤ 生成 HTML 更新报告

    本次运行结果自动生成鲜明直观的报告（三色横幅、状态色清单、分级徽章、异常置顶），按日期命名归档（如「NF更新报告-YYYY-MM-DD.html」），逐日累积成运行史。

阶段 4 验收要点：连续 7 天定时运行无中断；报告逐日归档无缺漏；抽查任意一天报告，其自检、回归、动态结果与数据库实际状态一致；异常项（若出现）在报告顶部可见且有处置记录。

诚实边界：每日扫描受网络可达性与官方平台更新节奏影响，不承诺零延迟捕获，时效性以官方公告为准（需求基线红线⑤）。报告中的事件条目仅作线索，涉标准变更须经核实与人工确认才改动专业库。

七、阶段 5 · 角色扩展：从单场景到四类角色

机制跑通、一期内容转正、每日任务运转后，按「依赖关系」而非「平均用力」的顺序扩展角色——每个扩展都复用同一套机制，只是加载不同的工作流与卡片类型：

表 3 角色扩展顺序与前置条件
顺序 角色 加载内容 前置条件
第 1 批 学生 · 课设毕设 选型决策树（管径→壁厚→管材→防腐→阴保→安全间距→试压）、分阶段检查清单、说明书模板与规范引用格式 一期规范卡与公式卡已转正；引擎回归通过
第 2 批 教师 章节自测题生成模板、课程设计任务书模板、讲义关联定位（规范变更推送联动） 学生场景跑通；规范状态链已核实
第 3 批 场站运维 故障卡（表象→原因→排查→处置）、作业卡与作业票清单、应急卡（介质×事故矩阵）、维保卡 需补充现场真实资料（脱敏）；事件库分级机制已运转
第 4 批 工程设计 选型取值卡、工况校核矩阵、材料腐蚀对照卡、报审资料检查清单、在役评估链路卡 规范卡覆盖面扩展至设计规范；工程案例入库

扩展节奏由内容决定：机制框架在阶段 1 已一次性建好，后续扩展不再改机制、只灌内容——扩展慢不是技术问题，而是「权威内容需要专业输入」的必然节奏（需求基线分期落地的诚实版）。

贯穿全程的三条不可妥协项：

  • 未转正的卡片不参与回答——任何阶段都不为进度牺牲这条规则；
  • 未通过回归的公式拒算——宁可拒绝计算，不输出未验证的数值；
  • 非官方渠道资料不入库——版权与准确性双重红线。

下一步：你只需做两件事

① 确认首个切入场景（推荐「学生日常学习」——规范查询 + 公式计算，随时可改）；② 把第一批正版规范与教材文件放入工作目录。之后阶段 1 的骨架搭建即可启动——搭完骨架立刻进入文件灌入，你会看到第一张真实卡片从你的文件里长出来。
